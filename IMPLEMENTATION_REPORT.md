# Отчёт о реализации P0 ssh_relay 0.6.0

Дата: 2026-07-29.

## Реализовано

- машинный JSON-протокол для `exec` и `sudo-exec`;
- коды процесса `0`, `10`, `11`, `12`, `13`;
- безопасный receipt без полного текста команды;
- `transaction_id`, `receipt_id`, `command_hash`, `receipt_hash`, `previous_receipt_hash`;
- `partial_success` и `unknown`;
- безопасные метаданные `change_target` и `change_description`;
- проверка self-hash последней записи до запуска изменяющей команды;
- блокировка уже записанного `transaction_id` до запуска основной команды;
- legacy anchor для последней receipt-записи 0.5.x;
- режим receipt-файла `0600`, `umask 077`, проверка конечной символической ссылки;
- сохранение session-файла при потере ответа после отправки запроса;
- совместимость нового daemon с обычным запросом CLI 0.5.x;
- сохранение текстовой семантики stdout, stderr и удалённого exit code.

## Выполненные проверки

```text
python -m py_compile ssh_relay.py
python tests/test_machine_protocol.py
python tests/test_local_tcp_protocol.py
python ssh_relay.py --version
проверка --help для всех подкоманд
```

Проверены:

- успешная risky-операция;
- удалённый exit code `7`;
- ошибка записи receipt после успешной команды;
- неопределённый результат команды;
- отсутствие полного текста тестовой команды в receipt;
- вычисление и проверка self-hash;
- обнаружение подмены receipt;
- legacy anchor 0.5.x;
- параметры защиты receipt-файла;
- отклонение повторного `transaction_id`;
- сохранение session-файла при потерянном ответе;
- реальный локальный TCP-обмен CLI–daemon с подменённым SSH-транспортом;
- старый запрос CLI 0.5.x к daemon 0.6.0;
- новый JSON-запрос и корректный `stop`.

## Не проверено

- реальное подключение Paramiko к SSH-серверу;
- фактическая запись JSONL на Linux;
- `sudo-exec` с реальным sudo-паролем;
- реальные сетевые разрывы и timeout SSH;
- два одновременно запущенных именованных daemon на разных серверах;
- интеграция с кодом `agent-safe`.

Перед ручным прогоном изменённый daemon необходимо остановить и запустить заново.

## Ограничения реализации

- hash-цепочка не является цифровой подписью;
- сторонние параллельные записи в тот же JSONL не поддерживаются;
- для системного receipt требуется доверенный родительский каталог;
- повторный `transaction_id` пока не обеспечивает идемпотентность команды и должен контролироваться вызывающей стороной;
- `inspect`, `exec-script` и `sudo-exec-script` относятся к следующим этапам.
